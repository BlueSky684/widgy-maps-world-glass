Widgy 27.0.1: City and several Location fields are empty in JavaScript outside the editor
Investigation date: 2026-10-01
Status: reproducible on the tested iPhone; internal cause and workaround unconfirmed

SUMMARY
Native text and native variable interpolation can display City and precise
Location components outside the editor. The same variables become empty
strings when inserted into JavaScript text sources outside the editor.
Both Script and Async + No main() are affected in this test. JavaScript
itself executes successfully. Changing to Async does not restore the data.

The installed Widgy version was reported as 27.0.1. This is evidence from
one device, not a claim that all installations or OS versions are affected.
The reporter's actual city, address and coordinates are intentionally omitted.

REPRODUCTION
1. Import the diagnostic linked below as a separate widget.
2. It defines a Text variable named async_city, sourced directly from
   Location > City. No variable depends on another variable.
3. Compare these text-layer sources:

   Custom Text:
   [${widgy.async_city}]

   Javascript > Script:
   function main() { return '[' + String("${widgy.async_city}") + ']'; }

   Javascript > Async + No main():
   sendToWidgy('[' + String("${widgy.async_city}") + ']');

   Javascript > Async + No main(), Promise completion:
   Promise.resolve().then(function () {
     sendToWidgy('[' + String("${widgy.async_city}") + ']');
   });

4. The async control uses no Location input:
   sendToWidgy('RAN at ' + new Date().toISOString().slice(11, 19) + ' UTC');
5. Render outside the editor and compare with the editor.

EXPECTED
The native and JavaScript text layers resolve the same current Location
variable, or the app documents a supported mechanism/limitation for this case.

EDITOR COMPARISON
Synchronous probes of City, Country, Location Name, DMS and full Longitude
populate inside the editor. IMG_9644 also confirms that the async City,
Promise City, DMS and full Longitude populate inside the editor, while
IMG_9643 shows these fields empty outside it.

OTHER CONTROLS
- Static text variables reach synchronous JavaScript correctly.
- Fresh City aliases and a combined native location packet do not resolve
  the outside-editor failure in JavaScript.
- Direct image JavaScript also lacked City in a separate probe, so failure
  is not confined to a JavaScript-variable-to-image-variable chain.
- Text vs Real Number variable types both expose Decimal coordinates with
  one decimal under the tested default formatting. A synthetic numeric input
  retains all its decimal digits.
  This does not mean the device location itself has only one-decimal precision:
  native DMS data demonstrates that more precise location data is available.
- The latest async diagnostic is local text only: no images, fetch calls,
  geocoding services or map endpoint are involved.

INTERPRETATION AND LIMITS
The evidence is consistent with a Location-variable substitution/evaluation
problem outside the editor, shared by the tested sync and async sources.
It does not identify the internal cause or prove that no workaround exists.
Delaying an already-substituted empty string cannot recreate its missing data.
A city should not be guessed from one-decimal coordinates as an exact result.

QUESTIONS FOR THE DEVELOPER
Is this native Location -> JavaScript substitution pattern supported outside
the editor? Why do Decimal sources resolve while other Location fields do not?
Is there a supported raw/full-precision Location accessor, dependency setting,
or source-evaluation option that should be used instead?

PREPARED ALTERNATIVE (NOT ENABLED OR PHONE-VERIFIED)
tools/widgy-city-map-script.mjs prepares one phone-side async request to
BigDataCloud using current native Max 5 coordinates, followed by a map URL
with city and coordinates. No native City input or city variable chain.
IP-derived, mismatched or empty city responses fall back to the coordinate
map URL. Tests use synthetic local responses only; no location was submitted
to the provider. A request that never settles is subject to Widgy timeout.
The provider permits calls only from the device whose current location is
used, not from this workspace or the Vercel map server.

The review widget keeps lookup disabled until permission to share current
precise coordinates with BigDataCloud is given. While disabled it uses the
existing coarse map inputs. The production dashboard is unchanged.
